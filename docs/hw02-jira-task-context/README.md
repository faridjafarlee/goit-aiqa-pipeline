# ДЗ 2. Збір контексту задачі

Скіл `jira-task-context` бере задачу з Jira і складає з неї один контекст-файл. Цей файл потім читають наступні скіли пайплайну, першим іде грумінг вимог.

## Задача

Реальної задачі продукту в мене немає, тому я створив власну навчальну задачу в навчальній Jira:
KAN-7 "[Jafarli] Password Recovery: Forgot Password and Reset Link"
(https://neoversity-ak.atlassian.net/browse/KAN-7). Вона повʼязана з епіком KAN-1 "User Registration Form".

## Файли

- `skills/jira-task-context/SKILL.md`: сам скіл.
- `skills/jira-task-context/references/field-maps.md`: карта полів Jira для типів задач проєкту KAN. Я зібрав її через MCP з метаданих проєкту: у KAN є Task і Subtask, вимоги лежать у полі `description`, окремих кастомних полів для AC немає.
- `skills/jira-task-context/references/output-template.md`: структура контекст-файлу.
- `skills/jira-task-context/references/context-example.md`: еталонний контекст-файл, зроблений на реальній задачі KAN-7 і звірений з Jira, щоб скіл тримав однаковий рівень деталізації.
- `skills/references/language-rule.md`: мова скіла, спільна для всіх скілів пайплайну.
- `Task Runs/KAN-7/KAN-7-context.md`: контекст-файл, отриманий під час запуску.

## Як працює скіл

1. З URL або ключа бере сайт і ключ задачі та створює папку `Task Runs/<ключ>/`.
2. Через Atlassian MCP робить один запит `getJiraIssue`, тільки з полями з карти і з текстом у Markdown.
3. За типом задачі вибирає карту полів. Якщо карти немає або опис порожній, зупиняється й пише причину.
4. Вкладення MCP віддає лише як список назв. Тому скіл просить людину завантажити потрібні файли в чат, а ті, що не завантажені, позначає як "наявне, але не оброблене".
5. Розкладає опис, таблиці, AC і коментарі по секціях і не переписує їх своїми словами. Коментар, що уточнює вимогу, ставить поруч із нею. Коментар з новою вимогою йде в окрему секцію. Коментарі про процес не потрапляють у файл. Якщо джерела дають різні значення, обидва записуються з позначкою, а вирішувати їх буде грумінг.
6. Перед збереженням ще раз звіряє файл з даними Jira, перевіряє формат і перезаписує файл повністю.

Якщо Atlassian MCP недоступний, немає доступу до задачі чи немає обовʼязкових даних, скіл зупиняється, називає причину і файл не створює. Браузер, прямий REST API та інші обхідні шляхи заборонені. У Jira скіл нічого не пише, бо акаунт навчальної Jira спільний.

Мова скіла українська, тексти з тікета зберігаються мовою оригіналу. Рекомендована модель Sonnet з фіксованою версією, effort Medium.

- KAN-1 подано лише як фон, його вимоги в контекст не перенесено.
