# KAN-900 - QA чекліст

Вимоги: Task Runs/KAN-900/KAN-900-requirements.md

## Чекліст

### REQ-1: Поле типу `email` з label "Email" та зірочкою обовʼязковості

- [ ] REQ-1.1: Поле Email присутнє на формі реєстрації
- [ ] REQ-1.2: Поле має тип `email` (REQ-1: тип `email`)
- [ ] REQ-1.3: Над полем відображається label "Email" (REQ-1: label "Email")
- [ ] REQ-1.4: Поруч із label відображається зірочка обовʼязковості

### REQ-2: Placeholder "name@example.com"

- [ ] REQ-2.1: У порожньому полі відображається placeholder "name@example.com" (REQ-2)

### REQ-3: Валідація виконується при сабміті форми

- [ ] REQ-3.1: Натискання сабміту з невалідним значенням у полі Email показує помилку валідації під полем

### REQ-4: Порожнє поле: помилка "Email is required"

- [ ] REQ-4.1: Сабміт форми з порожнім полем Email показує помилку "Email is required" (REQ-4)

### REQ-5: Значення без символу `@` або без домену після `@`: помилка "Enter a valid email address"

- [ ] REQ-5.1: Значення без символу `@` (напр. `anna.example.com`) при сабміті показує помилку "Enter a valid email address" (REQ-5)
- [ ] REQ-5.2: Значення без домену після `@` (напр. `anna@`) при сабміті показує помилку "Enter a valid email address" (REQ-5)
- [ ] REQ-5.3: Значення з `@` і доменом (напр. `anna@example.com`) при сабміті не показує помилки формату

### REQ-5a: Значення з кількома символами `@` вважається невалідним: помилка "Enter a valid email address"

- [ ] REQ-5a.1: Значення з двома символами `@` (напр. `anna@@example.com`) при сабміті показує помилку "Enter a valid email address" (REQ-5a)

### REQ-6: Більше 254 символів: помилка "Email must not exceed 254 characters"

- [ ] REQ-6.1: Валідний email довжиною 254 символи приймається без помилки довжини (REQ-6: не більше 254 символів)
- [ ] REQ-6.2: Email довжиною 255 символів при сабміті показує помилку "Email must not exceed 254 characters" (REQ-6)

### REQ-7: Пробіли на початку й у кінці значення обрізаються перед валідацією

- [ ] REQ-7.1: Значення ` anna@example.com ` (з пробілами на початку й у кінці) при сабміті не показує помилки формату

### REQ-8: Помилка відображається під полем червоним текстом

- [ ] REQ-8.1: Текст помилки валідації розташований під полем Email
- [ ] REQ-8.2: Текст помилки валідації відображається червоним кольором

### REQ-9: Після виправлення значення і повторного сабміту помилка зникає

- [ ] REQ-9.1: Після заміни невалідного значення на `anna@example.com` і повторного сабміту помилка під полем Email не відображається

### REQ-10: Валідація також виконується при втраті полем фокусу (blur)

- [ ] REQ-10.1: Введення `anna@` і перехід фокусу з поля Email показує помилку "Enter a valid email address" без сабміту форми (REQ-5)

## Обмеження покриття

- REQ-6: невідомо, чи 254 символи рахуються до чи після обрізання пробілів (знахідка грумінгу «лишилось»),
  тому граничні перевірки REQ-6.1/6.2 виконуються на значеннях без пробілів.

---

Що показує приклад:
- Поле введення отримало базовий набір лише в межах вимог (присутність, тип, label, placeholder, валідація).
- Граничні значення 254/255 є, бо вимога містить числову межу. Негативні перевірки є, бо поле інтерактивне.
- Кожне точне значення має цитату; пункти атомарні й зрозумілі без requirements-файлу.
- Невирішену знахідку грумінгу записано як явне обмеження покриття, очікуваний результат для неї не вигадано.
